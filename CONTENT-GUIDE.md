# Action Global News content guide

How to add stories to actionglobalnews.com so every page, index and feed stays consistent.
The 7am and 7pm scheduled tasks follow this file. Read it fully before publishing.

## Ground rules (AdSense and editorial)

These rules are why the site can be approved for Google AdSense. Breaking them gets it rejected again.

- **Original work only.** Every story is written in our own words from sources we read. No copied
  sentences, no rewritten wire copy, no reproduced paragraphs.
- **No third-party content modules.** Do not add RSS or headline feeds, news tickers, embedded
  YouTube or live-TV players, TradingView or other market widgets, or "headlines from other
  newsrooms" blocks. `node _tools/agn.mjs check` fails if `data-feed`, `data-yt-`, `data-tv=` or
  `class="adslot"` appear anywhere.
- **No house ads.** Do not add "Advertisement" boxes promoting our own businesses. Display ads come
  from Google AdSense only (the `adsbygoogle.js` tag in `<head>`, publisher `ca-pub-3561679124556057`,
  matching `ads.txt`). Do not change the publisher ID.
- **Never invent facts.** Every number, date, name and quote must come from a page you actually
  read today, and that page must be linked in the text and listed under `sources`. If a fact is only
  in a search snippet, leave it out. Quotes: only exact wording from a published source, attributed
  to the outlet that published it, at most one or two per story. Never generate a quote.
- **Name and link sources.** Prefer primary documents (agency releases, court orders, company filings,
  SEC/EDGAR, CDC/WHO, php.net, etc.) and established newsrooms (AP, Reuters, BBC, NPR, PBS, CBS, ABC,
  Al Jazeera, The Colorado Sun). When two sources disagree, say so or report the range.
- **No invented people.** The byline is always "Action Global News Staff", edited by Zach Wennstedt.
  Do not create reporter names or personas.
- **Network content is labeled.** Stories about businesses that share ownership with the publisher
  (Eye To Ad Media, Aging Safely Baths, Showers4Less, PressReleaseForBusiness, USABusinessSearch,
  World VR Mall, allofus.one, etc.) must say "From our network" in the kicker and disclose the
  relationship in the first paragraph. Keep these rare; the daily briefs should be general news.
- **No medical, legal, tax or investment advice.** Explain what happened and point to official
  guidance.

## Story types

| Type | Length | Use for |
|---|---|---|
| `brief` | 250 to 400 words of body | One significant story from the last 24 to 36 hours |
| `explainer` | 1,500+ words | Context on a big ongoing story, with a table or chart built from real data |

A daily run should add **3 to 6 briefs**. Add an explainer when a story is big enough to need one
(about once or twice a week). Quality beats volume: two well-sourced briefs are better than six thin ones.

## Where things live

| Path | What it is |
|---|---|
| `_content/articles/<slug>.json` | The source spec for every story created with the tool (not published; Jekyll skips `_` folders) |
| `articles/<slug>/index.html` | The rendered article page (generated; do not hand-edit for new stories, edit the JSON and re-render) |
| `_tools/agn.mjs` | The generator and checker (Node 18+, no dependencies) |
| `index.html` | Home page. The lead story, side stack and "Latest reporting" block are rebuilt by the tool. Everything below them is hand-made desk sections. |
| `<desk>/index.html` | Desk pages. The block between `<!--AGN:DESK-->` markers is rebuilt by the tool. |
| `latest/index.html`, `authors/*/index.html` | Fully generated by the tool |
| `sitemap.xml`, `news-sitemap.xml`, `feed.xml`, `feed.json`, `data/search-index.json`, `llms.txt` (Articles section) | Regenerated by the tool |

Older articles (before 2026-10-22) were written by hand and have no JSON spec. The tool reads them
from their HTML, so they stay in every index. Do not delete them.

## Step by step

1. `cd C:\Users\zachw\Sites\actionglobalnews.com`, then `git pull --ff-only`.
2. Pick stories. Check what we already covered: `ls _content/articles` and `latest/index.html`.
   Do not repeat a story unless there is a real new development (then write a new brief that links
   the earlier one).
3. Research each story: read at least two reputable sources, ideally including a primary document.
   Write down the facts with their URLs before drafting.
4. Write the spec JSON (template below) in `_content/articles/<slug>.json`.
5. Render and rebuild everything:
   ```
   node _tools/agn.mjs all
   node _tools/agn.mjs check
   ```
   `all` renders every spec and then rebuilds the home page, desk blocks, /latest/, author pages,
   sitemaps, feeds, search index and llms.txt. `check` must print `check passed`.
   (To render one story only: `node _tools/agn.mjs new _content/articles/<slug>.json` then
   `node _tools/agn.mjs index`.)
6. Preview locally (for example `node C:/Users/zachw/overnight/static.js C:/Users/zachw/Sites/actionglobalnews.com 8841`)
   and look at the home page and each new article at phone width (390px) and desktop.
7. Commit only the files you changed, never `git add -A`:
   ```
   git add _content/articles articles index.html latest authors sitemap.xml news-sitemap.xml feed.xml feed.json data/search-index.json llms.txt <desk folders touched>
   git commit -m "Add N news briefs for <date>"
   git push origin main
   ```
   GitHub Pages serves `main`; the site updates a minute or two after the push.

## Spec template

Use single quotes for HTML attributes inside JSON strings (`<a href='...'>`) so you do not need to
escape double quotes. External links in the body use `target='_blank' rel='noopener nofollow'`.
Internal links are root-relative (`/articles/<slug>/`).

```json
{
 "slug": "lowercase-words-with-hyphens",
 "type": "brief",
 "section": "Business",
 "kicker": "Business · Brief",
 "published": "2026-10-22T07:05:00-06:00",
 "updated": "optional, same format, only when the story changes after publishing",
 "title": "SEO title, 50 to 65 characters, no site name",
 "h1": "The headline readers see. A full sentence that says what happened",
 "description": "Meta description, 140 to 160 characters, with the key fact and date",
 "standfirst": "Two or three sentences: what happened and why it matters.",
 "keywords": "comma, separated, search phrases",
 "takeaways": ["Three short factual bullets", "each with a number or date", "that a reader can act on"],
 "body": [
  "<p>First paragraph: who, what, when, with the main source linked: <a href='https://example.gov/release' target='_blank' rel='noopener nofollow'>agency release</a>.</p>",
  "<h2>A question-style subhead?</h2>",
  "<p>Context and detail.</p>",
  "<h2>What happens next</h2>",
  "<p>Dates, decisions pending, and what readers should do.</p>"
 ],
 "sources": [
  {"publisher": "Agency or outlet", "title": "Exact headline as published", "date": "October 22, 2026", "url": "https://..."},
  {"publisher": "Outlet", "note": "description, used when you do not have the exact headline", "date": "October 22, 2026", "url": "https://..."}
 ],
 "faq": [{"q": "A question people search for?", "a": "A one or two sentence answer taken from the story."}],
 "updateNote": {"when": "October 22, 2026, 3:10 p.m. MT", "text": "optional note shown at the top when a story changes"}
}
```

Field notes:

- `section` must be one of: AI, AI Agents, Arts & Design, Business, Colorado, Global Ecommerce,
  Health, Immersive, Markets, Outdoors, Real Estate, Science, Small Business, Technology, Travel,
  World. It decides the desk page and breadcrumb.
- `kicker` is shown above the headline: `<Section> · Brief`, `<Section> · Explainer`,
  `<Section> · Earnings`, `<Section> · Analysis`. The home page lead goes to the newest explainer or
  analysis from the newest day, so give long-form pieces an `Explainer` or `Analysis` kicker.
- `published` uses Mountain Time with the offset (`-06:00` during daylight time, `-07:00` from
  November 1 to March). Use the real time you publish, never a future time.
- `faq` is optional; when present the tool adds visible FAQ markup and matching FAQPage JSON-LD.
- Tables: `<table class='dtable'><caption>...</caption><thead>...</thead><tbody>...</tbody></table>`
  followed by a `<p><em>Source: ...</em></p>` line.
- Charts: `<figure class='chart'><h3>Title</h3><p class='cs'>Subtitle</p><svg viewBox='0 0 720 H' role='img' aria-label='...'>...</svg><figcaption>Source: ...</figcaption></figure>`.
  Build bars from real numbers only. `_content/articles/php2shell-php-vulnerabilities-what-website-owners-should-do.json`
  shows a working example. The first chart in an explainer becomes its home-page thumbnail.
- Other styles available: `<div class='pullquote'>...</div>`, `<ol class='steps'>...</ol>`.

## What the tool generates for each article

NewsArticle JSON-LD (author: Action Global News Staff, editor: Zach Wennstedt as a Person,
publisher: the NewsMediaOrganization, citation list from `sources`), BreadcrumbList, optional
FAQPage, Open Graph and Twitter tags, canonical URL, byline with publish and update dates, share
bar, key takeaways, sources list with the standards note, and the right rail with the five newest
stories. Images: new articles use `/images/agn-og.jpg` unless the spec has `"image": "/images/og/<slug>.jpg"`
and that file exists.

## Checklist before pushing

- [ ] Every fact traces to a linked source read today; no snippet-only facts.
- [ ] No sentence copied from a source (paraphrase, then compare).
- [ ] Quotes are exact and attributed to the outlet that published them.
- [ ] Brief body is 250 to 400 words; explainer 1,500+ with a real table or chart.
- [ ] `node _tools/agn.mjs check` prints `check passed`.
- [ ] Home page shows the new stories; /latest/ lists them under today's date.
- [ ] Viewed at 390px and desktop; no horizontal scroll, no console errors.
- [ ] Committed only the changed paths; pushed to `main`.

## Things not to touch

- `ads.txt` (publisher `pub-3561679124556057`), the AdSense `<script>` tag, `CNAME`, `robots.txt`.
- Policy pages (about, editorial-standards, ethics-ai-policy, corrections, privacy, terms,
  disclosure, contact) except to correct a fact; they describe how the site works now.
- `press-releases/` is filled by the `sync-releases` workflow, is noindexed and is not newsroom content.
- The `headline-snapshot` workflow still runs hourly and commits `data/feeds.json`, but no page reads that file any more. Never add feed modules back. (Changing workflow files needs a token with the `workflow` scope; Zach can disable it under GitHub, Actions, Refresh headline snapshot, Disable workflow.) Because of these bot commits, always `git pull --rebase` before pushing.
